# 《AI客来：街角咖啡屋》框架分析与下一步开发

更新时间：当前代码版本

## 1. 当前架构定位

项目当前是一个 Cocos Creator 3.8.8 + TypeScript 的轻量模拟经营原型。

当前目标：

```text
先保证离线可玩、流程稳定、性格差异明显，
再考虑真实 AI API、美术表现和长期成长系统。
```

当前核心循环：

```text
准备阶段
-> 进货 / 定价
-> 营业阶段
-> 顾客自由对话
-> 欲望变化
-> 购买 / 离店
-> 日终结算
-> 下一天
```

## 2. 分层结构

### core：经营状态与日流程

`GameManager.ts`

负责全局经营状态：

- 资金
- 声望
- 星级
- 天数
- 阶段
- 库存
- 售价
- 成本
- 营收
- 利润
- 利润目标
- 技能点
- 成就

当前库存规则是“未售库存保留”，不会在打烊时自动清零。

`DayManager.ts`

负责每日顾客流程：

- 按星级生成顾客数量。
- 从已解锁顾客池中随机抽取顾客。
- 逐个触发顾客进店。
- 顾客结束后切换下一位。
- 全部顾客结束后触发结算。

`EventBus.ts`

负责模块之间的轻量通信：

- 游戏状态变化。
- 顾客到店。
- 顾客离店。
- 成交。
- 一天结束。
- 技能变化。
- 成就解锁。

### data：静态配置

`ProductData.ts`

商品数据包含：

- id
- 名称
- 梯度
- 解锁星级
- 成本
- 建议售价
- 描述
- 保质类型
- 标签

商品标签是当前顾客性格差异的关键，比如：

- 美式：coffee、fast、bitter、takeaway
- 拿铁：coffee、mild、popular、comfort
- 牛角包：dessert、food、fast、takeaway、popular
- 蓝山手冲：coffee、premium、story、bitter

`CustomerData.ts`

顾客数据包含：

- id
- 姓名
- 显示性格名
- 性格描述
- 对话偏好
- 原始 likes/dislikes
- 喜欢关键词
- 讨厌关键词
- 偏好商品标签
- 价格敏感度
- 耐心轮数
- 决策风格
- 初始购买欲望
- 解锁星级

这让 6 类顾客能从数据层产生差异，而不是只靠代码里写死。

### ai：本地 AI 规则与未来 Prompt

`AIManager.ts`

当前仍是本地规则 AI。它负责：

- 根据玩家输入计算本轮欲望变化。
- 根据顾客性格选择不同回复模板。
- 根据欲望和耐心决定购买、离店或继续考虑。
- 购买时从有库存商品中选择。
- 优先在符合顾客偏好标签的商品中随机选择。

当前欲望计算结构：

```text
话术匹配分
+ 商品偏好分
+ 价格接受分
+ 性格特殊规则
= 本轮欲望变化
```

`PromptBuilder.ts`

为后续真实大模型 API 保留。当前已经包含：

- 顾客性格。
- 喜欢/讨厌关键词。
- 偏好商品标签。
- 价格敏感度。
- 耐心轮数。
- 决策风格。
- 商品标签。
- 当前购买欲望。
- 玩家输入。
- 历史对话。

### ui：Cocos 界面层

`MainUI.ts`

负责：

- 显示资金、天数、声望、阶段。
- 根据阶段显示/隐藏主面板。

当前阶段规则：

- `Prep`：显示进货界面。
- `Business`：显示聊天界面，同时保留只读库存/售价面板。
- `Result`：显示结算界面。
- `GameOver`：显示失败/结算信息。

`ShopPrepUI.ts`

负责：

- 刷新商品列表。
- 准备阶段允许进货。
- 营业阶段只显示库存和售价，不允许进货。

`ProductItemUI.ts`

负责：

- 商品名称。
- 成本。
- 建议售价。
- 当前售价。
- 当前库存。
- 售价输入。
- 数量输入。
- 购买按钮。
- 运行时调整布局，减少文字重叠。

`ChatUI.ts`

负责：

- 玩家输入。
- Enter 发送。
- 调用 AI 回复。
- 欲望进度条刷新。
- 顾客购买/离店处理。
- 对话结束结果显示。
- 结果停留后切换下一位顾客。
- 聊天记录滚轮/触摸滑动。

`ChatBubbleUI.ts`

负责：

- 显示说话角色。
- 显示文本。
- 根据文本长度调整气泡高度。

`ResultUI.ts`

负责：

- 显示日终结算。
- 显示利润目标。
- 显示失败原因。
- GameOver 时禁止继续下一天。

## 3. 当前系统状态

- 完整单日经营闭环。
- 多天经营。
- 库存跨天保留。
- 有库存商品才可被顾客购买。
- 购买后库存减少。
- 商品定价影响欲望。
- 顾客性格影响欲望。
- 顾客性格影响回复风格。
- 顾客性格影响商品选择。
- 顾客购买商品带随机性。
- 日终结算。
- 利润目标。
- 简单技能和成就接口。
- 基础 UI 阶段切换。
- 聊天输入和滚动优化。

- 内容安全审核。
- 本地存档。

- 网红打卡事件完整链路。
- 完整美术表现。
- 新手引导。
- 正式 ScrollView prefab 结构。

## 4. 当前技术取舍

### 为什么继续使用本地规则 AI

比赛现场可能没有稳定网络。当前本地规则 AI 已经能演示：

- 不同性格顾客。
- 自由文本影响购买欲望。
- 定价影响经营结果。
- 库存影响购买商品。

因此真实 AI API 应该作为下一阶段增强，而不是当前稳定性的前置条件。

### 为什么库存不再自动报废

之前“鲜制品打烊报废”会造成玩家误以为第一天商品全部卖完。当前阶段更需要清晰反馈：

```text
只有顾客购买才扣库存。
未售商品进入第二天。
```

后续如果恢复报废机制，必须在结算界面明确列出报废数量和商品名。

### 为什么聊天滚动先用脚本实现

当前场景已经有 `BubbleList` 节点，直接把它改成完整 ScrollView 会涉及场景结构和 prefab 重绑。现在先用脚本支持滚轮/触摸拖动，降低破坏已有绑定的风险。

## 5. 后续开发路线

### 优先级 A：稳定演示版

目标：比赛现场能稳定演示 3-5 分钟。

任务：

- 固定一条演示路线。
- 调整顾客生成，让 1 星阶段也能看到更多性格。
- 优化聊天气泡和商品列表视觉。
- 结算日报增加更自然的建议文案。

### 优先级 B：真实 AI 接入

目标：让项目更贴合 AI 主题。

任务：

- 接入一个稳定模型 API。
- 固定输出格式。
- 增加格式校验。
- 增加超时和失败回退。
- 保留当前本地规则作为离线兜底。

### 优先级 C：成长系统完善

目标：让多天经营更有长期目标。

任务：

- 存档。
- 星级升级提示。
- 技能升级界面。
- 成就提示。
- 装修 buff。
- 解锁商品和顾客提示。

### 优先级 D：美术和交互打磨

目标：让作品更像完整游戏。

任务：

- 咖啡屋背景。
- 顾客头像/立绘。
- UI 主题统一。
- 按钮位置和文字尺寸进一步调整。
- 新手引导。

## 6. 当前项目一句话总结

当前项目已经从“能跑通流程的原型”升级为“具备经营策略、顾客性格差异和基础交互优化的可演示版本”。下一步最值得做的是稳定演示路线和真实 AI 接入二选一，不建议同时大改美术、存档、API 和成长系统。
