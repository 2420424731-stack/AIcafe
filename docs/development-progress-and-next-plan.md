# 《AI客来：街角咖啡屋》开发进度与下一步规划

更新时间：当前代码版本

## 1. 当前项目总结

项目已经从最小闭环推进到“经营数值 + 顾客性格差异 + 基础 UI 可用性优化”的阶段。

当前可玩的主流程：

```text
开店前准备
-> 进货 / 定价 / 查看库存
-> 开始营业
-> 顾客进店
-> 玩家自由文本对话
-> 顾客购买或离店
-> 自动切换下一位顾客
-> 全部顾客结束
-> 日终结算
-> 下一天继续经营
```

当前重点不是接真实大模型，而是先让本地规则版本稳定、可演示、能体现 AI 主题比赛中的“对话影响经营结果”。

## 2. 已完成阶段

### 第一阶段：稳定最小闭环

已完成：

- 进货。
- 定价。
- 库存记录。
- 资金扣除。
- 开始营业。
- 顾客生成。
- 顾客对话。
- 购买欲望变化。
- 购买或离店。
- 下一位顾客切换。
- 日终结算。
- 下一天。
- 结算后禁止继续给上一位顾客发消息。

关键修复：

- 顾客最多会在设定轮数内做出购买或离店决定，避免无限犹豫。
- 只有当前有库存的商品会被传给 AI 决策。
- 顾客结果停留 1.2 秒，避免刚显示就被下一位顾客清空。

### 第二阶段：完善经营数值

已完成：

- 售价过高会降低购买欲望。
- 售价合理会提高购买欲望。
- 商品条目显示当前售价和库存。
- 营业阶段仍显示库存/售价，但禁止继续进货。
- 顾客购买时优先从符合性格偏好的有库存商品中随机选择。
- 每日顾客数按星级变化。
- 日终结算显示利润目标和是否达成。
- 未售库存保留到次日，不再无提示清零。

当前库存规则：

```text
进货 -> 库存增加
顾客购买 -> 库存减少
打烊 -> 库存保留
下一天 -> 继续显示剩余库存
```

### 第三阶段：完善顾客性格差异

已完成：

- 6 类顾客都有独立配置：
  - 喜欢关键词
  - 讨厌关键词
  - 偏好商品标签
  - 价格敏感度
  - 耐心轮数
  - 决策风格
- 商品已有标签：
  - coffee
  - fast
  - bitter
  - mild
  - popular
  - comfort
  - takeaway
  - dessert
  - food
  - sweet
  - relax
  - art
  - premium
  - story
- 本地 AI 欲望变化拆成：

```text
话术匹配分
+ 商品偏好分
+ 价格接受分
+ 性格特殊规则
= 本轮欲望变化
```

- 6 类顾客回复风格已经区分：
  - 社恐：短句、谨慎、怕强推。
  - 挑剔：专业、追问、重细节。
  - 文艺：氛围、故事、情绪价值。
  - 社牛：轻松、互动、闲聊。
  - 赶时间：直接、效率、少废话。
  - 纠结：需要明确推荐。

### UI 可用性优化

已完成：

- 商品条目运行时自动调整布局，减少文字和按钮重叠。
- 对话输入框支持 Enter 发送。
- 聊天区域支持滚轮和触摸拖动。
- 聊天气泡高度根据文字长度自适应。
- 超出聊天可视区的旧消息会隐藏，避免压到输入框。

## 4. 当前测试清单

### 经营闭环测试

1. 打开 `Main.scene`。
2. 进货至少 2 种商品。
3. 检查资金减少、库存增加。
4. 调整售价。
5. 点击开始营业。
6. 检查营业阶段仍显示库存和售价。
7. 和顾客对话。
8. 检查购买欲望是否变化。
9. 检查顾客是否在耐心轮数内购买或离店。
10. 检查结束时是否显示：
    - `结果：购买了XX`
    - `结果：未购买`
11. 检查购买后库存减少。
12. 所有顾客结束后进入结算。
13. 点击下一天。
14. 检查未售库存是否保留。

### 性格差异测试

测试用例见：

```text
docs/customer-personality-test-cases.md
```

重点观察：

- 正确话术是否加分。
- 错误话术是否扣分。
- 赶时间顾客是否更快决策。
- 纠结顾客是否更依赖明确推荐。
- 顾客购买商品是否更贴近标签偏好，但仍有随机性。

## 5. 已知取舍

- 当前不接真实大模型 API，避免比赛现场网络不稳定影响演示。
- 当前库存不做打烊报废，因为现阶段更需要玩家清楚看到“卖出才减少库存”。
- 当前聊天滚动由脚本实现，不依赖重新制作 Cocos ScrollView 结构。
- 当前 UI 仍是功能可用优先，不是最终美术品质。
- 当前没有完整存档系统，重开预览会从初始状态开始。

## 6. 下一步建议

### 第四阶段：接入真实 AI 或增强本地 AI

二选一：

- 如果比赛强调 AI API：接入真实模型。
- 如果比赛更强调稳定演示：继续增强本地规则和固定演示路线。

建议任务：

- 完善 `PromptBuilder` 输出格式。
- 设计真实 AI 固定返回字段：
  - 对话内容
  - 欲望变动值
  - 当前购买欲望
  - 购买决策
  - 购买商品
- 加格式校验。
- 加失败回退到本地规则。

### 第五阶段：展示效果强化

建议任务：

- 咖啡屋背景图。
- 顾客头像或立绘。
- 更清晰的库存/售价表格。
- 更完整的结算日报文案。
- 新手提示。
- 固定比赛演示路线。

### 第六阶段：长期经营系统

建议任务：

- 本地存档。
- 装修 buff。
- 更完整的技能升级界面。
- 成就弹窗。
- 星级升级提示。
- 复购顾客。
- 网红打卡事件。

## 7. 当前一句话结论

项目现在已经具备可以演示的核心玩法：玩家通过进货、定价和自由文本对话影响顾客购买欲望，顾客会根据性格差异做出不同反馈，并随机购买符合偏好的库存商品，最终形成每日经营结算。
