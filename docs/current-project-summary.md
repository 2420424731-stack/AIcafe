# 《AI客来：街角咖啡屋》当前项目总结

更新时间：当前代码版本

## 1. 项目当前状态

《AI客来：街角咖啡屋》目前已经从“最小可玩闭环”推进到“可演示版本”。

当前版本已经具备：

- 开店前进货。
- 商品定价。
- 库存显示。
- 库存跨天保留。
- 营业阶段顾客进店。
- 玩家自由文本对话。
- 顾客购买欲望变化。
- 顾客购买或离店。
- 顾客购买商品随机。
- 顾客购买后扣库存。
- 日终结算。
- 下一天继续经营。
- 6 类顾客性格差异。
- 商品标签与顾客偏好匹配。
- Enter 发送对话。
- 聊天记录可滚动。
- 聊天气泡自适应高度。
- 阶段界面自动显示/隐藏。

当前核心循环：

```text
进货 / 定价
-> 开始营业
-> 顾客进店
-> 玩家自由文本对话
-> 顾客根据性格、价格、库存、话术改变购买欲望
-> 顾客购买或离店
-> 结算
-> 下一天继续经营
```

## 2. 当前已完成的阶段

### 第一阶段：稳定最小闭环

已完成：

- 进货。
- 定价。
- 扣除资金。
- 开始营业。
- 顾客生成。
- 顾客对话。
- 顾客购买或离店。
- 自动切换下一位顾客。
- 全部顾客结束后进入结算。
- 点击下一天回到准备阶段。

关键修复：

- 顾客不会无限犹豫。
- 顾客最多会在耐心轮数内做出购买或离店决定。
- 结算后不能继续给上一位顾客发消息。
- 顾客最终结果会停留一小段时间，不会立刻被下一位顾客清空。

### 第二阶段：完善经营数值

已完成：

- 售价过高会降低购买欲望。
- 售价合理会提高购买欲望。
- 商品条目显示成本、建议售价、当前售价、库存。
- 营业阶段仍显示库存和售价。
- 营业阶段禁止继续进货。
- 未售库存保留到次日，不再打烊自动清零。
- 顾客购买时只会购买有库存商品。
- 顾客购买商品时，优先从符合性格偏好的商品中随机选择。
- 每日顾客数量按星级变化。
- 日终结算显示利润目标和达成情况。

当前库存规则：

```text
进货 -> 库存增加
顾客购买 -> 库存减少
打烊 -> 库存保留
下一天 -> 继续显示剩余库存
```

### 第三阶段：完善顾客性格差异

已完成：

- 6 类顾客拥有独立配置：
  - 喜欢关键词
  - 讨厌关键词
  - 偏好商品标签
  - 价格敏感度
  - 耐心轮数
  - 决策风格
- 商品拥有标签，用于和顾客偏好匹配。
- 本地 AI 欲望计算拆成：

```text
话术匹配分
+ 商品偏好分
+ 价格接受分
+ 性格特殊规则
= 本轮购买欲望变化
```

6 类顾客差异：

- 社恐内向型：短句、谨慎、怕强推。
- 挑剔达人型：重视专业、细节、口感描述。
- 文艺青年型：喜欢氛围、故事、情绪价值。
- 社牛自来熟型：喜欢互动、闲聊、熟客感。
- 赶时间上班族：重视效率，耐心更低，更快决策。
- 纠结选择困难型：需要明确推荐和缩小选择范围。

## 3. 当前 UI 状态

当前界面已经支持基础阶段切换：

- `Prep`：显示进货界面。
- `Business`：显示聊天界面，同时保留只读库存/售价面板。
- `Result`：显示结算界面。
- `GameOver`：显示失败/结算信息，禁止继续聊天和进入下一天。

聊天界面已优化：

- 支持 Enter 发送。
- 支持鼠标滚轮滑动。
- 支持触摸拖动。
- 气泡高度会根据文本长度调整。
- 超出聊天可视范围的旧消息会隐藏，避免压到输入框。
- 顾客结束时显示最终结果：
  - `结果：购买了XX`
  - `结果：未购买`

## 4. 当前主要脚本

### core

- `GameManager.ts`
  - 资金、声望、星级、库存、售价、成交、结算、利润目标、技能、成就。
- `DayManager.ts`
  - 每日顾客数量、顾客队列、顾客切换、声望变化。
- `EventBus.ts`
  - 模块之间的事件通信。

### data

- `ProductData.ts`
  - 商品数据和商品标签。
- `CustomerData.ts`
  - 顾客性格、关键词、商品偏好、价格敏感度、耐心、决策风格。

### ai

- `AIManager.ts`
  - 本地规则 AI、欲望计算、回复模板、购买/离店决策、随机选购商品。
- `PromptBuilder.ts`
  - 后续真实 AI API 的 Prompt 上下文。

### ui

- `MainUI.ts`
  - 状态栏和阶段界面控制。
- `ShopPrepUI.ts`
  - 进货、定价、营业阶段只读库存显示。
- `ProductItemUI.ts`
  - 商品条目、库存、售价、布局优化。
- `ChatUI.ts`
  - 输入、Enter 发送、对话、购买结果、滚动、顾客切换。
- `ChatBubbleUI.ts`
  - 聊天气泡文本和高度自适应。
- `ResultUI.ts`
  - 日终结算、利润目标、失败信息。

## 5. 当前技术取舍

### 暂不接真实 AI

当前仍然使用本地规则 AI。

原因：

- 本地规则更稳定。
- 比赛现场可能无网络。
- 当前阶段重点是先把性格差异和经营闭环调顺。

后续真实 AI 可以从 `AIManager.reply` 接入，并保留本地规则作为兜底。

### 库存不再自动报废

之前打烊自动清空 `Fresh` 商品，会让玩家误以为商品第一天都卖完了。

当前规则改为：

```text
只有顾客购买才减少库存。
未售库存保留到第二天。
```

如果后续恢复报废机制，需要在结算界面明确显示报废商品和数量。

### 聊天滚动先用脚本实现

当前没有重做正式 Cocos `ScrollView` 结构，而是在 `ChatUI` 中用脚本支持滚轮和触摸滑动。

这样可以避免破坏已有 `Main.scene` 和 prefab 绑定。

## 6. 当前测试建议

### 基础流程测试

1. 打开 `Main.scene`。
2. 进货 2-3 种商品。
3. 检查资金减少、库存增加。
4. 点击开始营业。
5. 检查营业阶段仍显示库存和售价。
6. 输入话术，也可以按 Enter 发送。
7. 检查购买欲望是否变化。
8. 检查顾客最终显示：
   - `结果：购买了XX`
   - `结果：未购买`
9. 如果购买，检查库存是否减少。
10. 所有顾客结束后进入结算。
11. 点击下一天。
12. 检查未售库存是否保留。

### 顾客性格测试

测试用例文件：

```text
docs/customer-personality-test-cases.md
```

重点测试：

- 社恐是否讨厌强推。
- 挑剔是否喜欢专业描述。
- 文艺是否喜欢故事和氛围。
- 社牛是否喜欢互动话术。
- 赶时间是否更快做决定。
- 纠结是否需要明确推荐。

## 8. 当前一句话结论

当前项目已经具备可以演示的核心玩法：玩家通过进货、定价和自由文本对话影响顾客购买欲望，顾客会根据性格差异做出不同反馈，并随机购买符合偏好的库存商品，最终形成每日经营结算。
